The first algorithm I implemented in a machine learning class was a perceptron. I remember staring at the training loop because it looked too small to count as learning. There was no optimizer package, no probability distribution, and no hidden layer. It was a dot product, an `if`, and three additions.

That small loop matters. The perceptron is the cleanest place to see what a classifier actually learns: not labels, but a boundary between them.

In [part one](/blog/ml-from-scratch-gradient-descent), we fit a line that predicts a number. The perceptron makes that prediction categorical: given two measurements, return class `+1` or class `-1`. This binary classification maps to the mathematical formulation in [Rosenblatt's original work](http://www.ling.upenn.edu/courses/cogs501/Rosenblatt1958.pdf) and is covered in the [perceptron section of the scikit-learn documentation](https://scikit-learn.org/stable/modules/linear_model.html#perceptron).

## Start with a score

Represent one sample as a vector `x = [x1, x2]`. Give each feature a weight and add a bias:

```text
score = w1*x1 + w2*x2 + b
```

The score can be any real number. A threshold turns it into a class:

```text
prediction = +1  if score >= 0
prediction = -1  if score < 0
```

That threshold also defines the decision boundary. Every point where the model is exactly undecided satisfies:

```text
w1*x1 + w2*x2 + b = 0
```

With two features, this equation is a line. On one side, the score is positive. On the other, it is negative. Training means rotating and shifting that line until the classes fall on opposite sides.

## Learn only from mistakes

Suppose the true label is `y`, either `+1` or `-1`. If the prediction is correct, do nothing. If it is wrong, update each weight toward the mislabeled sample:

```text
w = w + learning_rate * y * x
b = b + learning_rate * y
```

Why does that work? Take a positive sample that the model incorrectly put on the negative side. Its score is below zero. Adding a positive multiple of `x` to `w` increases the next dot product with that sample. The boundary moves toward classifying it as positive.

For a negative sample predicted as positive, `y` is `-1`, so the same formula subtracts `x`. One rule handles both cases.

<Callout label="the key idea">The perceptron has no smooth loss to minimize. A correct sample produces no update. A mistake is the entire learning signal. This is the mistake-driven update first described by Frank Rosenblatt in his 1957 paper The Perceptron: A Probabilistic Model for Information Storage and Organization in the Brain (http://www.ling.upenn.edu/courses/cogs501/Rosenblatt1958.pdf).</Callout>

Watch the green line. It stays still after a correct prediction and jumps after a mistake. The update counter changes only on those jumps. This is online learning in its simplest form: inspect one example, make one decision, correct immediately.

The complete implementation is about 30 lines without plotting:

```python
def fit_perceptron(X, y, epochs=20, lr=0.1):
    weights = [0.0] * len(X[0])
    bias = 0.0

    for _ in range(epochs):
        mistakes = 0

        for features, label in zip(X, y):
            score = sum(
                weight * value
                for weight, value in zip(weights, features)
            ) + bias
            prediction = 1 if score >= 0 else -1

            if prediction != label:
                for index, value in enumerate(features):
                    weights[index] += lr * label * value
                bias += lr * label
                mistakes += 1

        if mistakes == 0:
            break

    return weights, bias
```

There is one useful detail in that code: stop when a full pass makes zero mistakes. If the data is linearly separable, the perceptron convergence theorem guarantees that this eventually happens. This mathematical guarantee was proven in [Novikoff's 1962 paper](https://projecteuclid.org/journals/annals-of-mathematical-statistics/volume-33/issue-3/On-Convergence-Proofs-on-Perceptrons/10.1214/aoms/1177698623.full). The theorem does not promise the widest-margin boundary or the same boundary on every run. Sample order changes the path and can change the final line.

## Where it fails

In 1969, Marvin Minsky and Seymour Papert made the perceptron's limitation famous in [Perceptrons](https://mitpress.mit.edu/books/perceptrons): one straight boundary cannot solve XOR. Put positives at the top-left and bottom-right of a square, with negatives at the other two corners. No single line separates them.

If you run this training loop on XOR, it keeps correcting one point and breaking another. The weights never settle. That failure is not a coding bug. The hypothesis class is wrong for the geometry.

This is why multilayer networks matter. A hidden layer can combine several boundaries into a nonlinear region, as demonstrated in the [Multi-Layer Perceptron Wikipedia entry](https://en.wikipedia.org/wiki/Multilayer_perceptron). But adding layers creates a new problem: the hard threshold has no useful derivative. We will need smoother functions and gradient-based training to assign credit through the network.

The perceptron still shows up in practical systems because the update is cheap, streaming-friendly, and easy to inspect. More importantly, it exposes the skeleton beneath classification: weighted evidence, a boundary, a prediction, and a correction.
